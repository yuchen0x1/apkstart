### 上游提交适配结论

- **8 语种界面**：上游新增英/俄/越/西/葡/日/韩词典。本仓库已有中/英/西/越/俄五语界面与更严格的词典回归，因此不直接合并上游词典文件；本轮把上游俄语、越南语中能对应本仓库源文案的缺失条目补入，俄语覆盖从 344 条增至 680 条（57.0%），越南语从 344 条增至 654 条（54.9%），其余未翻译条目继续回落英文。日语/韩语/葡语未加入界面：上游词典只能覆盖本仓库 1192 条源文案中的 325 / 413 / 110 条，且不含自动化面板的完整词条，加入后会出现大面积英文夹排，未达到本仓库对受支持语言的覆盖门槛。
- **自定义系统镜像**：本仓库已有 `src/core/images.js` 镜像适配层（导入、体检、启用、恢复默认、独立 AVD），不采用上游直接填写目录的实现；用户数据隔离和失败回退更完整。
- **后台内存优化**：已移植「主窗口隐藏时暂停状态轮询、回到前台立即补刷」和「托盘按状态指纹更新、重建时清理旧图标与定时器」，并覆盖系统面板轮询。
- **构建与 CI 部分**：上游 MSIX 语言资源、Gitee 发行说明回填不属于本仓库构建链（本仓库不发 MSIX、不使用 Gitee 发布），未移植。

### 新增 Issue 逐条核对

- **#150 DNS 服务器可选**：本轮实现。设置 → 网络、声音与后台新增「DNS 服务器」，可选国内（阿里 / 腾讯，默认）、Cloudflare、Google；仅在开启网络加速时传给模拟器，未知值回落国内，关闭加速时不传 `-dns-server`。`test/auto-test.js` 增加参数层回归。
- **#151 俄语/英语补丁**：本仓库已有英语与俄语界面；本轮并入上游俄语缺失条目，不引入第三方补丁包。英语覆盖保持既有 1192 条。
- **#152 安装应用失败**：上游日志只显示 `install-failed`，没有安装包、ADB 原始错误或设备状态，无法复现根因。本仓库安装链在失败前检查 ABI、`/data` 剩余空间和运行时可用性，失败时返回具体错误而不谎称重试；本轮未修改安装逻辑，也不宣称已修复该报告。
- **#149 ADB 启动崩溃**：报告没有版本、日志或复现步骤。本仓库使用每实例独立 ADB 路由，并在终止/接管前校验进程身份；本轮没有新增改动，保留为需要原始日志的待复验项。
- **#148 真正的便携版**：本仓库便携包可把运行时放在 exe 旁边的 `runtime/`，但配置、APK 缓存、AVD 与图标仍在用户数据目录（Windows 为 `%APPDATA%\apkstart`）。把全部用户数据随包移动属于数据目录迁移/多实例边界，本轮未实现，不把「运行时便携」写成「整包便携」。

### 验证边界

完整 `npm test`、隔离 Electron 界面审计、`test/auto-test.js` 的 DNS 参数回归和 `test/i18n-test.js` / `test/i18n-language-test.js` 均需在发布前重新执行；上游报告者的显卡、系统版本、APK 与网络环境未在本机复验，不能据此关闭 #149 / #152 或宣称安装兼容性已根治。

## 2026-11-25 自动 GPU 恢复复核（v0.11.7）

本次通过 GitHub API 复核的上游 `main` 仍为 [`7e2c5503`](https://github.com/RoutineMiku/apkstart/commit/7e2c5503b908c0a4d55283c85244a8e09b2725c7)。自动 GPU 选择的相关实现来自两个既有提交：

- [`f172f906`](https://github.com/RoutineMiku/apkstart/commit/f172f9060a37bc736e3742f4c535ae35b927805e)：Windows AMD 的 `host` 启动禁用 Vulkan，并通过 `badGpuVulkanTried` 为同一 emulator 版本提供一次恢复尝试，避免历史 `badGpu=host` 记录长期迫使软件渲染。
- [`df7ef86d`](https://github.com/RoutineMiku/apkstart/commit/df7ef86dab6bad5ef50eabfe834fe9924de55cb5)：删除按 AMD 厂商无条件优先 `swangle` 的逻辑，默认 `host` 优先并保留软件渲染候选。`host` 后端选择不等于指定物理独显或证明客机已经采用硬件渲染。

本仓库此前已有 Windows AMD `-feature -Vulkan`、自动窗口的 `host` 优先和逐级回退，但仍沿用缺少原因、时间与环境证据的长期失败记录。本轮改为只接受明确 `GPU_INIT` / `GPU_MODE` 证据，对同一运行时、驱动与显示环境最多退避 24 小时；旧记录、过期或环境变化恢复正常候选顺序，原失败后端启动成功后清除记录。手动后端继续固定，低配、远程显示与明确嵌入模式保留各自的兼容策略。

本轮真实启动还发现 Qt `UpdateLayeredWindowIndirect failed` 单条宿主窗口合成警告被归为 `GPU_INIT`，会把仍在开机的客机提前中止并记入 GPU 失败记录。现仅保留诊断说明，不再以该警告单独证明安卓显卡初始化失败；行为回归覆盖警告跨过早期检查时间后仍继续开机且不写失败记录。

性能设置页同时区分当前实际运行参数和下次启动计划，另行标明下次选档依据；两组参数不同不必是用户刚保存过设置，也不能把下一次的策略解释为当前故障原因。最终完整 `npm test` 与隔离 Electron 界面审计已通过；PowerShell 原生窗口行为等用例按本机环境条件跳过，未改变系统策略。

本机使用生产 `EmulatorEngine`、隔离配置和全新 AVD，以自动模式及旧 `37.4.2.0|host` 记录启动，实际选择 `host` 并完成冷启动；日志确认 WHPX，客机 SurfaceFlinger 报告 NVIDIA RTX 5060 / OpenGL ES 3.1。本次运行时约 48 秒就绪（含前置检查总约 69 秒），仅为一次启动观察，不是性能提升基准。哔哩哔哩安装和 `MainActivityV2` 启动成功，Android 客机截图显示首次隐私确认页；未代用户同意或登录，未验收到应用主页面。视频性能、帧率、长时间稳定性和其他显卡环境未验收，少量首帧统计不能作为流畅度证据；不能据此关闭上游 #133 / #146 或宣称显卡兼容性已根治。Windows 物理显卡偏好 `UserGpuPreferences` 仍未移植。

## 2026-11-25 修复复核（v0.11.5）

上游 `main` 仍为 11 月 22 日的 `7e2c550`。本次又发现 [#147 请求 Linux 版](https://github.com/RoutineMiku/apkstart/issues/147)（11 月 25 日 14:06 创建）；本仓库已有 Linux x86_64 AppImage / deb，但这不包含 GNOME / Wayland 原生嵌入能力。自有仓库本轮检查无开放 Issue，也无开放 CodeQL、Dependabot 或 Secret Scanning 告警。

- 手动固定 GPU 在后续重试被替换，以及非 Windows 未探测显卡被强制归为软件渲染。
- 修正访问冲突的过度归因，并对 APK 必需 Vulkan 特性明确给出“尚未验证”的兼容性提示。

以上结论来自可重复夹具和回归测试，不能证明报告者的硬件兼容问题已根治；不替上游关闭 #133、#135 或 #146。`UserGpuPreferences` 尚未移植，实际 Vulkan 应用支持仍需客机能力与对应 APK 验收。

## 结论摘要

- 本轮完成四个仍能在本仓库落地的缺陷：Store 版只读运行时（#116）、跨进程嵌入被 `SetParent` 拒绝时的独立窗口兜底（#5）、嵌入窗口的 Android Home/Overview/Back 快捷键（#11）、启动窗口按主窗口显示器定位并提前隐藏主界面（#111）。
- 历史安全、路径、下载、DPI、窗口生命周期、方向和自动更新问题已有代码与测试覆盖，见下表；其中 #122、#127 这类宿主系统崩溃不能仅凭 ApkStart 日志归因。
- Linux GNOME 原生嵌入、macOS、Windows ARM64、Magisk、蓝牙等仍不属于本版本承诺范围；真实 Android 应用、混合 DPI、多显示器和商店沙箱仍需实际环境验收。

## 0.10.4 本轮新修

### #116：Windows Store 只读运行时

Store 包位于 `WindowsApps` 时，不能把包内 `runtime.dir` 当成可写目录。启动时现在先做真实写探针；只读包会按内容指纹复制到用户数据目录的 `runtime-store/<fingerprint>`，复制完成并重新核验 emulator、ADB 和系统镜像后才写入 `settings.runtime.dir`。磁盘空间不足、复制中断或包不完整都不会写入半成品，也不会覆盖用户已经选择的可写运行时。

### #5：SetParent 拒绝时的可用窗口

原生代理明确返回 `set-parent-failed`、`embed-parent-mismatch` 等拒绝原因时，应用窗口会尝试把模拟器恢复为独立窗口；独立窗口脱离失败则继续保留启动遮罩，不谎报已就绪。原始拒绝与脱离结果会保留在 `lastEmbedError` 和日志中。`emu=0` 等“没有找到窗口”仍走无头运行时恢复，不会误判为永久独立模式。

### #11：嵌入窗口快捷键

应用窗口现在支持 `Ctrl+H`（Android Home）、`Ctrl+O`（Overview/最近任务）和 `Ctrl+B`（Back），通过白名单 IPC 调用 ADB keyevent 3、187、4。快捷键只在宿主 shell 获得键盘焦点时生效；真实嵌入窗口焦点和特定游戏的快捷键冲突仍需复验。

### #111：启动窗口定位稳定化

打开应用窗口时，主界面可见就使用主界面所在显示器的工作区，否则使用光标所在显示器；主界面在应用窗口创建后立即隐藏，不再等待窗口代理完成才隐藏，减少启动时“左一下、右一下”的跳动。多显示器混合 DPI 的最终体验仍需对应硬件验收。

## 部分缓解或需要真实环境

- **#6、#15、#20、#29、#31**：诊断会区分无加速、GPU/窗口渲染冲突和超时，并提供 WHPX/AEHD/软件后端建议；没有报告者的 CPU、显卡和驱动，不能保证开机成功。
- **#7、#13、#16、#25、#65、#69、#81、#83、#90、#107**：安装、红果/抖音/番茄等特定 APK 的兼容性只能按 ABI、权限、网络和应用自身服务逐一验收；本仓库不把“能安装”写成“能正常使用”。
- **#47、#57、#62、#74、#79、#86**：项目本质仍使用 Android Emulator；运行时、镜像、网络和权限会占用磁盘与资源，README 已补充来源、权限和卸载说明。
- **#54、#55、#58、#82、#87、#89**：语言需求仍是持续补齐词条的功能项；当前中英文入口可用，西语/越南语/俄语不承诺全量覆盖。
- **#66、#77**：运行时和系统镜像体积无法消除，只能通过独立目录、清理入口、按需镜像和磁盘提示控制。
- **#98、#122**：更新回滚和 Electron/Chromium 启动边界已有防护；Windows 11 特定构建的 `STATUS_BREAKPOINT` 需要系统事件日志和最小复现，不能只靠应用层代码确认。
- **#127**：QEMU 退出码与蓝屏转储分别记录；蓝屏涉及第三方内核驱动、显卡或系统，未取得可复现转储前不归因于 ApkStart。
- **#114**：客机显示模式“请求成功”不等于应用实际 60/120 FPS，帧率仍需客机和应用测量。

## 平台或功能边界

- **#24、#88**：Linux x86_64 支持下载和独立窗口；Linux GNOME/Wayland 原生嵌入依赖不同窗口系统，当前不承诺。
- **#112**：macOS 不在当前打包目标和运行时支持矩阵中。
- **#126**：Windows ARM64 没有本版本的构建、签名和运行时资产，不能宣称支持。
- **#128**：Magisk/root 需要可刷写的客机镜像和启动链路，当前不内置、不自动安装。
- **#129**：蓝牙透传需要宿主驱动、客机协议和应用验收，当前能力表标记为不支持。
- **#85**：完整运行时可随发行包或从 Release 导入；轻量包默认按需下载，不能把运行时 ZIP 随意解压覆盖正在使用的 AVD。
