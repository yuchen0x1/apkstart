## 对照与取舍

|任务|ApkStart|对照项目与差距|本轮取舍|
|---|---|---|---|
|在 Linux 桌面运行 APK|Android Emulator/KVM，应用显示在独立窗口|Waydroid 的容器、宿主菜单与 Wayland 集成更深；它依赖不同的内核与显示栈|延续现有后端。优先修复影响全部 Linux 用户的更新问题|
|使用已有安卓设备|已有 ADB 连接模式|scrcpy 将设备服务端和桌面显示分开，控制真实设备无需重建 Android 镜像|保留设备模式，设备选择和重连可独立迭代|
|容器与浏览器交付|运行时和用户数据保存在本机|redroid、STF 和 Docker-Android 将宿主设备与浏览器客户端分开，需要 GPU、认证和会话隔离|不新建云服务|
|维护运行时|已有分组件部署与离线导入|Podman Desktop 和 Android Emulator Runner 把宿主准备与工作负载启动分开|首次使用直接说明下载来源，保留可复用组件|
|安装与更新|旧版按文件名模糊选包，计算本地哈希；公开 Release 后并行上传|electron-builder 区分安装器，AppImageUpdate 独立处理单文件，TUF 把可信元数据与下载源分开|签名绑定仓库、版本、文件与大小；Windows、AppImage、deb 分别处理|
|持续发布|已有双平台构建与版本同步脚本|Electron Forge 区分 make 与 publish，gh CLI 支持 draft 和发布资产|只让最终发布作业持有写权限，草稿验证完整后公开|

近期值得跟进的上游变化包括 AEHD 退役公告、Android Emulator Runner 对命令行工具的更新和 scrcpy 新发行。具体时间、提交、许可及来源以表中链接为准。发行前优先复查各项目最近 30、90、180 天的提交及 Release，更新本表中受影响的结论。

## 平台评估

基准能力是本机运行 APK、管理运行时、保存安卓数据并呈现可交互窗口。等级 A 表示维护现有产品，B 表示值得实施的适配，C 表示暂缓，D 表示当前定位不适用。

|目标|级别|宿主能力、权限、交互与成本|分发、更新及验证边界|
|---|---|---|---|
|Windows 10 x64 / Windows 11 x64|A|WHPX 或 AEHD、Win32 窗口管理、快捷方式与文件关联；沿用现有原生集成|在线 NSIS 与便携 ZIP。CI Windows Runner 不能代表两个系统版本和所有显卡|
|Linux x86_64 / Ubuntu / Debian|A|KVM、图形会话、宿主动态库；独立窗口，XDG 数据目录。桌面包管理器需可打开 deb|AppImage 与 deb；Ubuntu/WSL 有历史启动与安装记录，Debian 需独立验收|
|Fedora / Arch Linux x86_64|B|KVM 与图形会话类似，库名、FUSE 与桌面包关联不同；维护一个通用 AppImage 成本较低|沿用 AppImage，单文件更新；未承诺 RPM、AUR 或发行版实机通过|
|macOS Intel|C|HVF 可行，但现有运行时下载、窗口、安装和签名均未适配；Intel 单独维护收益有限|需 Intel 真机、签名与公证；无产物|
|macOS Apple Silicon|C|需 ARM64 AVD、ABI 兼容性验证、HVF 和独立桌面集成；现有 x86_64 镜像路径不可直接复用|需构建、签名与升级机群；无产物|
|Android 手机、平板、折叠屏|C|系统已提供 APK 安装和 Android 窗口；另做包管理器将改变核心用途，折叠布局也需独立维护|本轮不发行移动端|
|iOS / iPadOS|D|现有 Electron、ADB、宿主虚拟化与桌面窗口不适用；另建虚拟机产品成本高|无 App Store 产品或更新通道|
|桌面 Web、移动 Web、响应式 Web、PWA|D|静态页面能提供下载，浏览器无法按本项目方式管理本地模拟器进程、KVM 与磁盘|现有介绍网站继续提供下载入口|
|Chrome / Edge / Firefox 扩展|D|访问 USB 设备与本机运行 Android 属于不同能力；需要本机助手仍须安装桌面程序|无扩展包|
|Docker、NAS、私有化、云服务器|C|需 KVM 透传、GPU/显示、远程会话认证和数据隔离；维护与桌面安装器不同|不供应多租户镜像；桌面程序可本地离线导入|
|CLI|A|现有桌面程序参数支持双击文件和按包名启动；复用宿主运行时|随桌面程序分发；暂缓独立无头产品|
