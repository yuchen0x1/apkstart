## [0.9.3] — 2026-11-21

> 候选发行说明：新增修复仍待集成与最终门禁确认；不表示已正式发布或完成最终验收。

### 修复

- 整合主线设置与应用清单持久化保护：读取权限或 I/O 错误不以默认值覆盖原文件；损坏数据先备份再恢复，保存采用独占随机暂存文件、文件刷新及原子替换。配置合并拒绝非法分区类型与未知键，健康应用记录和开放式元数据保留。
- 普通应用启动与 Wi-Fi 抢修不再自动清空应用数据；重置由主进程再次确认。扩容、锁文件与缓存维护先确认目标运行时可安全操作，保留下载断点、其他 AVD 与未知镜像。
- 公开下载入口及每次重定向均要求 HTTPS，拒绝降级到 HTTP；定位写入按实际写入字节数计数并补齐短写。校验响应长度、范围及来源身份；缺少可靠身份时改为完整单源传输，多镜像拼接要求可信摘要并在完成后核验。
- 禁用未经可信校验的 AEHD 自动下载，以及对缓存安装脚本的提权执行。不自动安装第三方驱动；硬件加速可使用 Windows 内置虚拟化功能或启动已安装的驱动服务。需要新装 AEHD 时，请通过官方 SDK Manager 手动安装，不要运行来源不明的缓存脚本。
- 分包可做安装前兼容性检查并按正确格式导出。ZIP 重名或目录损坏会被拒绝；应用恢复只对本次安装使用的设备写入私有数据。
- 共享同步先校验暂存文件再替换，读取不完整或文件仍在写入时不传播删除。停止采用协作式取消，在限定时间内等待在途任务收尾；已经发出的文件或设备 I/O 无法撤销，等待超时也不等于全部 I/O 已停止。
- 应用外壳只拥有主题、显示和导航权限；关窗清理捕获该次操作对应的确切客户端，并排队执行，避免旧操作误清理新客户端。退出等待在途操作和外壳停靠，重复关窗不提前销毁代理。系统切换和应用库操作互斥，不向未接入库的系统误投安装请求。
- Provider 状态未知不视为已停止；停止失败或无法确认停止时如实报告，不宣称已安全切换。取消切换是请求停止后续步骤并等待在途操作收尾，不是立刻停止或回滚已经发出的操作。

### 体验

- 系统卡片使用准确的任务 ID 继续或重试；切换期间提供「取消切换」，取消请求尚未收尾时显示进行中，停止失败保留错误反馈。硬件加速检查的中英文提示明确说明仅在必要时请求系统授权，不自动安装第三方驱动。

### 安装与升级

| 平台 | 安装文件 | 安装或升级方式 |
|---|---|---|
| Windows 10/11 x64，安装版 | `ApkStart-0.9.3-Setup.exe` | 同一用户、同一安装形态覆盖安装到原目录；不要先卸载。 |
| Windows 10/11 x64，便携版 | `ApkStart-v0.9.3-win64-portable.zip` | 退出后解压或替换程序文件；不要覆盖或删除自选运行时、AVD 和数据目录。 |
| Linux x86_64，AppImage | `ApkStart-0.9.3-x86_64.AppImage` | 赋予执行权限后运行；应用内更新要求能在原路径替换文件，否则退出后手动换包。 |
| Debian / Ubuntu x86_64 | `ApkStart-0.9.3-amd64.deb` | 使用系统包管理器安装或升级；应用不静默安装 deb。 |

- 从 [本项目 GitHub Releases](https://github.com/yuchen0x1/apkstart/releases) 获取对应文件。本版桌面包不内置 Android 运行时，首次部署按需从官方源下载；Windows 也可导入已有的兼容运行时整包。Windows 7/8、macOS 及 ARM 宿主不在本次发布范围内。
- 同平台、同安装形态的覆盖升级以复用已有数据为目标；退出程序和它启动的运行时后，先备份用户数据目录、自选运行时／AVD、共享目录及重要存档。由旧版离线安装包迁移时，尤其要备份可能位于安装目录 `resources/runtime` 下的运行时与数据；不要把升级回滚当作数据备份。不保证跨安装形态、旧离线整包、直接从上游／第三方构建迁移或降级兼容。无匹配的更新资产或应用内更新失败时，从本项目发行页手动下载对应包。
- Windows 的 ApkStart 可执行文件与安装器没有本项目的 Authenticode 代码签名，系统可能提示未知发布者或 SmartScreen。正式发布链对更新清单做 Ed25519 签名，应用内更新用内置公钥验签并核对资产；手动下载可和同一发行页的 `SHA256SUMS` 比对。它们不提供 Windows 发布者身份，也不应作为绕过系统或组织安全策略的依据。

### 应用兼容范围

- Linux 使用模拟器独立窗口，不提供 Windows 的窗口嵌入、APK 文件关联与每应用快捷方式。独立 QEMU 系统若尚未接入 ApkStart 应用库，请在该系统的窗口内操作，或切回内置档位。
- APK／分包预检只能根据包内容和运行环境提示风险，不能保证安装后正常运行；实际取决于目标镜像、Android 版本、ABI 与 ARM 转译、Google Play 服务及宿主硬件等。应用备份与恢复私有数据还要求应用允许 `run-as`；备份里只有安装包时，重装不会恢复聊天记录或存档。

### 验证边界

- 新增修复的最终测试结论待集成后的统一门禁确认；本候选文档不声明最终测试通过、性能提升或发布成功。
- Node 回归覆盖语法、生命周期、下载、同步、安装与数据保护等逻辑。合成 APK 是测试输入，fake ADB（模拟设备响应）通过临时目录或替身验证命令选择和失败行为，不是实机 APK 安装、同步或私有数据恢复验收。
- `npm run test:electron` 和 `npm run test:ui` 使用真实 Electron / Chromium 渲染进程、沙箱和 preload；内存 IPC 夹具代替产品主进程，不连接真实设备或部署运行时。CI 的 Windows 与 Linux 能力分支均跑在 Windows runner 上；夹具截图仅证明界面呈现，不代表原生 Linux 桌面、Android 客机画面或 Windows 原生窗口嵌入。
- 既有 WSLg 记录不是本次最终代码快照的验收，也不等于裸 Linux 桌面或 KVM 实测。
- 真实 Android Emulator／QEMU 启停、WHPX／KVM 加速、宿主级窗口嵌入，以及真实安装器、旧版覆盖升级和在线更新／回滚，需要分别在对应平台和安装形态验收，不能由上述回归推定通过。

## [0.9.2] — 2026-11-21

### 修复

- Windows 安装版更新必须同时确认安装器退出成功、主程序非空且版本精确匹配，缺失或损坏的版本文件不再视为更新成功。
- 安装前验证备份完成及当前用户的恢复写权限，失败时停止安装；每次使用独立恢复目录，重试不会覆盖上一次的备份。
- 用户取消 UAC 时不改写未变的旧版文件；同版本安装尝试写入持久凭条，阻止失败后自动循环安装及备份膨胀，保留显式手动重试。
- 更新失败时保留安装包、待安装凭条及备份；即使失败记录写入失败，也不会触发成功清理。回滚未经确认时不自动重启。
- 更新失败通知兼容旧版 UTF-8 BOM 记录，区分已恢复、未安装和恢复未确认，不再一概宣称已回到旧版。

### 测试

- 增加 Windows PowerShell 临时目录执行用例，覆盖安装失败、版本缺失或损坏、备份/回滚失败及失败记录无法落盘；补齐启动通知回归。

- 修复 Android 方向枚举与安装元数据持久化，保留用户显示偏好；ARM 故障根据运行中客机能力诊断，不盲目切镜像、重灌或承诺重试。
- 显式安卓数据目录优先，多系统目录遵守运行时配置与 Linux XDG 约定。
- 下载失败先取消并等待其它分块结束，再关闭共享文件；取消保留有效断点，不再继续重试或写入已关闭的文件。
- 卸载确认前不清理数据，不全局终止其它安卓工具；保留共享文件、自选目录的其它资料和链接指向的外部文件。

  `Get-Content -Raw | ConvertFrom-Json` 读 `resources\app\package.json`，而 Windows
  PowerShell 5.1 的 `Get-Content` 默认按 ANSI(GBK) 解码。`package.json` 里的中文描述
  被解成乱码后连带破坏了 JSON 结构（实测报「未终止的字符串」），`version` 于是读成空。
  而核对逻辑对空值是宽容的（为了兼容没有 package.json 的旧包），结果就是
  **「只看 exe 在不在」** —— 装错版本也不会回滚。改成
  `[IO.File]::ReadAllText($pkg, [Text.Encoding]::UTF8)` 显式按 UTF-8 读；
  `catch` 里把失败原因写进 `update.log`，下次读不到能直接看到原因。
- 测试补上真实形态的回归：成功路径写入「UTF-8 无 BOM + 完整中文描述」的
  `package.json`。已验证这版测试在旧实现下会失败、新实现下通过。

### 验证
- 用真实的 `ApkStart-0.6.3-Setup.exe`（1,492,979,083 字节）在本机安装版上跑完整流程：
  `backup ok=True` → `installer exit 0` → `after install: exe=250400768 ver=0.6.3`

## [0.6.3] — 2026-11-16

> 0.6.2 修好了黑屏，但更新器本身还留着一个能让人「更新完就打不开」的坑。
> 本版只做这一件事，不动画面逻辑。

### 修复
- **安装版自动更新可能把安装目录整个清空**：安装版此前是「下载完就直接
  `Start-Process /S`」——`Setup.exe` 既没有校验，失败也没有回滚。而 NSIS 安装器是
  「先卸旧、再解新」，中途任何一步失败（磁盘空间不足、杀软拦截、包体损坏、UAC 被拒）
  都会留下一个空目录，程序从此打不开。0.6.1 → 0.6.2 的那次更新实测就踩到了：
  安装目录被删掉，`%TEMP%` 里躺了 8 个解压失败的 `apkstart-upd-*`。
  现在改成四道保护：
  1. **下载后校验**：体积下限、与发布信息记录的大小一致、`MZ` 头、`PE` 签名位置，
     并算出 SHA-256 落盘。不合格的包根本不会被执行。
  2. **装前备份**：先 `robocopy` 备份现有程序到 `update\backup-<版本>`
     （跳过 1.4GB 的 `resources\runtime`，它随时能重新下载）；备份失败就放弃安装。
  3. **装后核对**：读 `resources\app\package.json` 的 `version`，必须等于目标版本，
     而不是只看安装器退出码。
  4. **失败回滚**：核对不过就把备份整目录还原成旧版本，照常重启 ——
     最坏情况只是「这次没更新上」，不会变成「打不开」。

### 测试
- 新增 8 个安装版用例，其中两个是**真机执行**：用真 PowerShell 跑生成的脚本，
  把安装器换成「删空安装目录」来复现事故，断言程序被完整还原、版本仍是旧的；
  另一条走成功路径，断言新版本被识别、备份被清理。

### 修复（上游对齐）
- **嵌入窗口的 Z 序（黑边 / 未填满 / 点击失效 / 点不动「同意」的真因）**：模拟器窗口原先
  被挂成宿主窗口的子窗口，和 Electron 的网页层（`Chrome_RenderWidgetHostHWND`）是**兄弟**，
  Electron 会持续把网页层抬到最前 —— 黑底盖住安卓画面，鼠标全被网页层吃掉。
  现在改为挂到网页层**之下**，Z 序与命中测试天然优先；网页层尚未建好时先挂宿主，
  由 `EnsureReparent()` 在后续巡检里补挂。同时**不再**给嵌入窗口设 window region
  （带 region 的 Qt/GL 子窗口会让点击坐标错位，旋转后 region 尺寸不匹配还会露黑边），
  嵌入时主动清掉旧版本可能留下的 region。
- **横竖屏改为真正的手机 / 平板排版切换**：以前是「改完 wm size 再给模拟器发 Ctrl+←」，
  那只会把画面转 90°，安卓侧排版没变。现在只改逻辑显示尺寸并锁 `wm user-rotation 0`
  （竖屏 720×1280@320dpi ≈ 360dp 手机排版，横屏 1280×720@320dpi ≈ 640dp 平板排版），
  并打开 AVD 的方向/加速度传感器；全屏按钮直接等于横屏排版。旋转时先退出最大化再改尺寸，
  窗口尺寸限制在屏幕可用区内，`wm size` 变更后连续 6 轮贴合收敛。
- **虚拟机没网导致「点同意后黑屏」**：新增网络体检（`ip -o addr` 拿 IPv4 + `cmd wifi status`
  交叉确认，不用 ping —— 安卓多路由表 + shell 权限让 ping 经常误报）。启动成功后主动体检并
  在没网时明确写日志；拉起应用前最多等 20 秒网络，**只等不重启**（之前那版会在安装/启动途中
  停掉虚拟机再冷启动，直接变成「应用打不开」）。等待时对 `device-offline` 给 45 秒宽限。
- **清理缓存清不掉**：「清理可回收文件」新增「连当前 AVD 的快速启动快照一起清」选项
  （会先停运行时，真正回收几 GB）。
- **托盘单击无反应**：托盘图标单击即打开主界面（原来只绑了双击）。
- **启动时窗口被别的窗口压住**：嵌入完成后短暂置顶再撤销，只借一次 Z 序抬升，不长期霸占。

### 新增
- **重置安卓数据**：清空 `/data` 用户分区 + 已装应用记录 + 快速启动快照，把 AVD 还原成
  「刚装好系统」的干净状态；只动当前 AVD，保留 config.ini 等 AVD 身份文件，UI 二级确认。
- **修复网络**：一键重置安卓数据并重新开机，等到网络就绪（最长 4 分钟），成功后立刻存快照，
  下次恢复时网卡状态一起还原；应用清单保留，点开应用自动重装。
- **窗口代理诊断命令 `children`**：列出宿主窗口的直接子窗口（`hwnd` / 类名 / 可见性 / 尺寸），
  用来确认网页层是否真的存在 —— 换 Electron 大版本后若它改名或消失，嵌入会自动退回
  「挂宿主 + 主动抬升」的老路，这条命令能第一时间看出来。

### 变更
- 可见窗口的 GPU 后端顺序改为 `host → swangle → software → swiftshader`：裸 `software`
  在 WebView 重合成场景（点「同意」进主界面）容易整屏黑，`swangle`（ANGLE + SwiftShader）
  同样是软件渲染但合成路径正常；关加速的兜底档仍取 `software`。
- 重置数据时的快照参数改为 `-snapshot apkstart -no-snapshot-load`：不加载旧快照，
  但保存仍落到 `apkstart` 这个名字上（只给 `-no-snapshot-load` 的话会存进 `default_boot`，
  下次按名字找不到，等于白存一次）。

## [0.4.0] — 2026-11-15

> 稳定性 · 安全 · 兼容性大版本

这一版没有新功能噱头：把「会丢数据」「会被绕过」「已经过期」的三类问题先解决掉。
同步改为哈希三方合并、更新器补上路径穿越与回滚、渲染进程开启沙箱、Electron 33 升到 45。

### 新增
- **安装前兼容性检查**：选好 APK 后、真正安装之前，先按清单里能确定的事实给出结论
  （完全兼容 / 基本兼容 / 可能有问题 / 暂不支持），并列出具体理由：minSdk 是否超过运行时、
  targetSdk 是否过老、原生库架构（ARM64 / ARM32 / x86 / x86_64）能否直接执行或要走 ARM 转译层、
  是否依赖 Google Play 服务、是否要求摄像头/GPS/蓝牙等桌面没有的硬件、是不是拆分 APK 的分片。
  判定为「可能有问题 / 暂不支持」时会先问一句再装，不会装完才发现打不开。
  解析不到的信息一律标为未知，不猜结论。新模块 `src/core/compat.js`，19 个用例覆盖。
- **APK 导出与应用备份**：右键应用可「导出 APK…」到任意位置，或「备份应用…」生成一个
  含 `app.apk` + `meta.json` 的备份目录；「从备份恢复…」可重新装回。
  应用私有数据只在应用允许 `run-as`（debuggable）时才会导出成 `data.tar`；
  普通应用拿不到数据时会明确写出原因（`data-skip.txt`），**不会生成一个空包冒充备份成功**。
  新模块 `src/core/backup.js`，11 个用例覆盖（含命令构造与恢复分支）。
- **无人值守自检**：`APKSTART_SELFTEST=1` 启动后自动体检主窗口（preload 是否注入、
  IPC 是否真通、页面有无脚本错误）并落一份 JSON，供 CI 与打包产物验收使用。

### 安全
- **渲染进程开启 sandbox**：主窗口与应用窗口都从 `sandbox: false` 改为 `true`。
  preload 只依赖 `electron` 的 contextBridge/ipcRenderer/webUtils，沙箱下依然可用
  （已用真实渲染进程验证 81 个接口全部正常）。
- **IPC 统一来源校验**：90 多个通道在注册前统一包一层，只接受「主框架 + 页面位于
  src 目录内」的调用；iframe 冒充、页面被导航到外部站点后发起的调用一律拒绝。
  路径判定用 `path.relative` 做真实边界比较，不用 `startsWith`（`C:\app-evil` 也以
  `C:\app` 开头，是典型绕过）。新模块 `src/core/ipcguard.js`，11 个用例覆盖。
- **更新器加固**（`src/core/updater.js` + `src/core/zip.js`）：解压前逐条校验条目路径
  （拒绝 `../` 穿越、绝对路径、盘符、UNC、符号链接条目）、按 CRC 与声明大小校验内容、
  下载后核对大小并计算 SHA-256、解压后检查载荷确实是 ApkStart（有主程序 + resources），
  替换前备份将被覆盖的文件、失败自动回滚。16 个用例用真实恶意 ZIP 字节流验证。
- **共享目录同步重写**（`src/core/sharer.js`）：不再用「大小 + 修改时间 + 历史方向」判断一致，
  改为记录 base/local/remote 三份 SHA-256 做三方合并；两侧都改且内容不同时保留两份并生成
  冲突副本，绝不静默覆盖；写入走临时文件 + 原子替换；删除同步默认关闭，开启后也只移进回收目录。
  26 个用例覆盖，包括「Windows 上传过的文件在 Android 改（大小不变）必须同步回来」这条回归。

### 变更
- **Electron 33 → 45.3.2**（Chromium 156 / Node 24）：33 已于 2025-04 结束支持，
  当前受支持的是 43/44/45 三个大版本。升级后 `console-message` 事件改用新的单参数事件对象。
  原生模块 `@napi-rs/lzma`（N-API）在 Electron 45 下加载正常。
- 项目元数据统一指向 `yuchen0x1/apkstart`（下载器 User-Agent、CHANGELOG 链接、状态栏链接、
  安装包版权信息）；原作者的署名与 MIT 许可证保留在 LICENSE、About 页与 `contributors` 字段。
- **发版流水线随体积调整**：Electron 45 的壳层压后约 141 MB（上一版 99.6 MB），
  便携包体积闸门从 100 MiB 调到 160 MiB；超过 Gitee 单文件上限时明确跳过 Gitee 同步，
  不再产出需要手工拼接的 `.part1/.part2`。应用内更新只认 GitHub，不受影响。

### 修复
- **应用窗口关闭不彻底**（对齐上游 v0.3.7 的修复）：应用窗口右上角 ⨯ 之前直接调用
  Electron 原生 win.close()，绕过 AppWindow.close() 的收尾逻辑——安卓应用留在后台跑、
  模拟器窗口被重新挂回桌面；Alt+F4 / 任务栏关闭 / 系统关机路径同样受影响。
  现在 ⨯ 与 'closed' 事件都走完整收尾（摘下并藏好模拟器窗口 + force-stop 安卓应用）。
- **新文件不再白等一轮**：共享目录里刚出现的文件第一轮就会同步；
  只有「已同步过、又在毫秒内被改写」的文件才会本轮跳过（避免把半截内容当成新版本传出去）。
- **远端文件列表兼容两种 stat 输出**：`mtime|ctime|size|name` 与老的 `size|mtime|name`
  都能解析，不同 ROM 的 toybox/busybox 排版差异不再导致「设备被当成空目录」。
