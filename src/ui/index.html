第 1 步 / 共 3 步

三步开始：选一个安装位置 → 自动下载运行时 → 双击 APK 即用。

  • 要下载什么：adb 工具、Android 运行时引擎、Android 14 系统镜像（合计约 1.6 GB）。镜像就是安卓系统本身，这个体积压不下去了；不用整个下完才能用，装完这次以后不再下载。
  • 要多久：会先实测多个下载源、谁快用谁——GitHub 整包被限速时会自动改走官方源分组件下载（官方源实测可达每秒数 MB），通常 3~8 分钟。
  • 装在哪里：下一步选择。默认会推荐剩余空间最大的非系统盘，避免把 C 盘塞满。以后随时可以在「设置 → 系统集成」里改。
正在读取磁盘信息…
推荐 = 剩余空间充足的非系统盘。运行时与安卓数据（约 5~8 GB 起步，会持续增长）都会放在这里。
「自动」模式下 GitHub 整包实测太慢（如被限速到几十 KB/s）会自动切换官方源分组件下载；无论哪个源，下载完成都会校验官方校验值。

可以回到上一步换一个位置重试；也可以关闭向导，在「设置 → 运行状态」里查看详细原因与手动修复。

安装 Android 到虚拟磁盘

虚拟机窗口已打开。按下面 6 步操作一次，之后 ApkStart 会直接从磁盘启动，不再需要镜像。

  1. 启动菜单：用 ↓ 选到 Installation - Install Android-x86 to harddisk，回车
  2. Choose Partition：选 Create/Modify partitions；询问是否使用 GPT 时选 No
  3. cfdisk 分区：New → Primary → 容量直接回车 → Bootable → Write → 输入 yes → Quit
  4. 格式化：选 vda1 → 提示格式化时选 ext4 → Yes
  5. 引导与系统：Install GRUB 选 Yes；Install /system as read-write 选 Yes
  6. 完成：进度到 100% 后点下面的「我已安装完成」（ApkStart 会自动重启并接管）

如果之后提示 adb 未连接：在虚拟机窗口按 Ctrl+Alt+F1 进入终端，执行 setprop service.adb.tcp.port 5555、stop adbd、start adbd， 再按 Ctrl+Alt+F7 回到图形界面。

虚拟机资源（内存 / CPU）
正在读取本机配置… 自动值按「物理内存的 1/4、CPU 线程数的一半」计算：内存封顶 8 GB、核心封顶 8 个。再往上安卓侧基本吃不到收益，只会让快速启动快照（ram.bin 约等于分配的内存）跟着变大。手动选的值永远优先，不会被自动降级覆盖。

这是下一次打开应用时真正会用的参数。正在运行的安卓不会被打断，重开应用即按新参数启动。
资源策略
决定安卓虚拟机吃多少 CPU、画面多细腻。「均衡」会自动识别低配电脑并改用更保守的参数；「省资源」「流畅」是你手动指定的固定档，选了就不再自动降级。改完下一次打开应用生效。
正在检测…
检测不到硬件虚拟化（WHPX / AEHD）、内存偏小或 CPU 核心较少的电脑，会自动把内存固定到 2 GB、vCPU 2 个、分辨率 540 × 960、改用软件渲染，并保留快速启动快照。上面手动填的内存、核心数、画质、渲染后端永远优先，自动降级不会覆盖你的设置。
硬件加速
正在检测…
x86_64 安卓镜像要靠硬件加速才能正常开机。点「一键开启」会申请管理员权限，自动开启「虚拟机平台 / Windows 虚拟机监控程序平台」，或安装 AEHD 驱动，完成后按提示重启即可。若 BIOS 里没开虚拟化（AMD SVM / Intel VT-x），还需要先进 BIOS 打开。
画面与存储
扩容是就地做的：已装应用与存档都保留，只是下次打开应用会多花十几秒。
正在读取数据分区…
自动 = 先按机器性能挑一个（低配机器直接走软件渲染），失败后再逐级降级（显卡 → ANGLE → 纯软件），并把「拉起就崩」的后端记住。手动选一个后端就固定用它、不再自动切换，排障时很有用。
网络、声音与后台
给安卓指定国内公共 DNS（阿里 / 腾讯）。安卓默认走主机的 DNS，主机挂着 VPN 或走公司网时解析会拖到几百毫秒，视频类应用首屏发慢。内网域名访问异常时可关掉。
让应用提示音、视频声音正常播放。仅在你完全不需要声音、想再省一点 CPU 时关闭。
第二次打开应用只要几秒，代价是磁盘上多一份约等于内存大小的 ram.bin（内存调到 8 GB 时它就接近 8 GB）。磁盘紧张可以关掉：只影响启动速度，不影响应用与存档。
额外禁用 Play 商店、设置向导、打印服务等后台包，只留打开应用必需的环境。若遇到应用提示缺少 Google Play 服务，关掉此开关会自动恢复。
安卓环境只开机一次并常驻；之后打开应用不再重跑整个系统，只启动该应用并停掉其他应用进程。关掉最后一个窗口会清后台、停放容器，下次点开仍是秒进。
容器细节（高级）
降低进程优先级，CPU 优先让给 Windows 桌面；vCPU 数量不受影响。上面的「资源策略」已经会自动设置这一项。
没有应用窗口时，容器一律自动降到最低优先级停放。

显示与操作

应用窗口大小、嵌入方式与鼠标键位

应用窗口
随时按 F11 或右键托盘切换；全屏只放大窗口，不改变画面比例，切换不重启应用。
窗口模式下可拖动边框任意缩放；这里调的是 Android 内部渲染尺寸，越小越省性能。
「自动」会先尝试把安卓画面嵌进 ApkStart 的应用窗口；如果这台电脑嵌入后画面是黑的，程序会记住并改用模拟器自己的窗口，下次点应用直接把那个窗口显示出来 —— 不会再先给你一块黑屏。显卡驱动 / 软件渲染不兼容时，「始终用独立窗口」最省心。
鼠标键位
模拟器原生把左键当成手指点击，按住拖动就是滑动，无需额外设置。
模拟器默认把右键也当成一次点击（容易误触）。开启后右键只执行返回，不再触发点击。
平滑模式把一小段时间内的滚动合并成一次滑动手势，避免逐格抽搐，也不会每格都拉起一个 adb 进程。
侧键映射需要全局鼠标钩子。钩子只在 ApkStart 应用窗口处于前台时安装，失焦或关闭立即卸载，不会拖慢桌面。
以上映射只在应用窗口前台生效；切回桌面或关闭窗口后，鼠标行为完全恢复 Windows 原生。

系统集成

这里占用空间最大（数 GB）。改到非系统盘可大幅减轻 C 盘压力；修改后需重启软件，已存在的数据不会自动搬移（请手动复制后删除旧目录）。

下载与更新

下载源、网络代理、软件更新与失败反馈

下载与更新源
本版本从 GitHub（yuchen0x1/apkstart）检查更新与下载运行时，不走 Gitee；下载地址会逐个实测测速，从最快的开始。
检测到 Clash / v2rayN 等本地代理（系统代理已开启）时，下载与查新自动走代理——挂着代理直连 GitHub 往往只有几十 KB/s，走代理可达每秒数 MB。代理连不通会自动回退直连，本地地址永不走代理。
GitHub 直连太慢时，额外测速 ghfast.top / gh-proxy.com 这两个公开转发服务（只转发公开的发布文件，不涉及账号）。关掉后只用直连和你自己填的前缀。
填了就只用你填的前缀，不再尝试上面那两个公共镜像；留空则由「自动」逻辑决定。下载器会把它拼在真实地址前面。
大文件按块并行下载。默认 8 线程已经能跑满大多数家宽；网络稳定时可以试 16。
GitHub API 匿名限额 60 次/小时；带认证 5000 次/小时。默认自动读取本机 gh CLI 已登录的账号（gh auth token），无需填写；没有 gh CLI 或想用别的账号时才手动填 Token（github.com → Settings → Developer settings → Tokens，只读公开仓库即可）， token 只用于读取发布列表，不会上传任何东西。
