CORE FEATURES

像用本机软件一样用安卓应用

从安装到启动、从窗口到搜索、从数据到备份，ApkStart 把安卓应用接进 Windows 和 Linux 的日常使用习惯里。

选择或拖入 APK 即安装

支持选择文件、拖放安装；Windows 还可注册 .apk 文件关联，在资源管理器里双击即可开始解析和安装。

Windows 桌面快捷方式

应用名称和图标从 APK 中提取。Windows 可生成桌面与开始菜单快捷方式；Linux 请从 ApkStart 应用库启动，暂不生成应用菜单入口。

应用就是一个窗口

Windows 支持独立应用窗口、全屏、拖动缩放和按应用记住尺寸；Linux 使用模拟器自己的独立窗口，不提供 Windows 专有的窗口嵌入与鼠标钩子。

按平台选择启动入口

Windows 上可从开始菜单搜索快捷方式，任务栏按应用分组；Linux 从 ApkStart 应用库搜索和启动，暂不提供系统应用菜单集成。

文件双向互通

本机共享目录与安卓 /sdcard 双向同步，按内容哈希三方合并；两侧都改会保留两份并生成冲突副本，不静默覆盖。

装之前先告诉你行不行

兼容性检查覆盖系统版本、原生库架构、Google Play 依赖、硬件权限和拆分 APK，结论分四档并给出理由；拿不准的标「未知」。

导出与备份

可导出 APK，或生成 app.apk + meta.json 备份目录并一键装回；读不到私有数据时如实说明原因，不冒充「备份成功」。

运行时按需部署

按需下载运行时与 Android 14 系统镜像，支持测速选源、断点续传和本地整包导入，也可接管或复用已有运行时。

HOW IT WORKS

从双击到启动，四步直达

没有模拟器控制台，没有多余界面——用户看到的只有应用本身。

从应用库或快捷方式启动

在 ApkStart 应用库选择已安装应用。Windows 还可使用快捷方式触发 ApkStart.exe --launch 包名；Linux 暂不生成每个应用的桌面菜单入口。

按需拉起运行时

运行时未启动则自动拉起，默认使用 Android 14（API 34）Google Play x86_64 镜像；空闲可回收，也可接管本机已有运行时。

解析真实入口启动

按系统解析出的 LAUNCHER 入口启动，而不是猜测 APK 里的主 Activity，并做存活观察与失败恢复。

窗口即应用

窗口自动改标题、换真实应用图标、按竖屏比例摆放——全屏居中或自由窗口，Windows 上可按 F11 切换。

运行时由 ApkStart 自持管理 · Windows 位于 %APPDATA%\apkstart\runtime · Linux 使用 XDG 数据目录
REQUIREMENTS

配置要求

Windows 可选用 WHPX / AEHD，Linux 使用 KVM；没有硬件加速也能回退到软件模拟，但启动和操作会明显变慢。

项最低推荐
系统 Windows 10 x64（1903+）或 Linux x86_64 Windows 11 或主流 x86_64 桌面发行版
CPU 4 逻辑核；Windows 开启 VT-x / AMD-V，Linux 启用 KVM（未开启时走软件模拟） 8 核及以上
内存 8 GB 16 GB 及以上
磁盘 约 8 GB 可用空间（运行时 + 镜像 + 数据分区 + 快照） 20 GB 及以上（装大型游戏更宽裕）
显卡 无硬性要求（无加速时自动软件渲染） 支持 OpenGL ES / Vulkan 的独显或核显
网络 首次在线部署需访问 Google 官方源（也可导入本地运行时） —
Windows 7 / 8 与 macOS 不支持——项目面向 Windows 10/11 x64 与 Linux x86_64。Windows 建议在 BIOS 开启虚拟化并启用「虚拟机平台」功能，或使用内置 AEHD 驱动；Linux 需确认当前用户可使用 /dev/kvm。
数据目录可以迁移——Windows 可在「设置 → 桌面与文件」中修改运行时和安卓数据目录，Linux 使用 XDG 数据目录；已装应用、存档和快照与程序文件分开存放。
